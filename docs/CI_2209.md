# The GD 2.2091 CI build (Geode 6, Windows preview)

Two workflows build two files from the same commit:

| | GD 2.2081 (Geode 5) | GD 2.2091 (Geode 6) |
|---|---|---|
| Workflow | `.github/workflows/multi-platform.yml` | `.github/workflows/multi-platform-2209.yml` |
| Platforms | Windows, macOS, iOS, Android 32/64 | Windows only (Mac and Android in 2.0.1, iOS waits for Geode's bindings) |
| Artifact | `GucciBot (all platforms)` | `GucciBot GD 2.2091 (Geode 6, Windows)` |
| File in it | `nigelx1.guccibot.geode` | `GucciBot-<version>-GD2.2091.geode` |
| SDK | from mod.json (5.10.1) | tag 6.0.0-alpha.2 |
| Bindings | `bindings-ref: d641858` in the workflow | 7a670e9 + `patches/bindings-g6-copyable-renames.patch`, from CMakeLists.txt (no `bindings-ref`, which would skip the patch) |
| build-geode-mod | `@main` (floats) | `@61a56c6` (pinned) |
| Geode CLI | latest | v4.0.1 |
| SafetyHook | `#main` (floats) | `#f44cc07` (pinned) |
| Install | `install_ci_build.bat [commit]` into the game Geode's CLI points at | `install_ci_build.bat -Gd2209 -Folder <copy> [-Commit <sha>]`, only into a test copy |

The 2.2091 workflow runs on `workflow_dispatch` (any branch: `gh workflow run multi-platform-2209.yml --ref <branch>`) and on pushes to port-2209 and master (master only once the 2.2091 code is merged there). Its last step checks the package before uploading it: the binary, the seven FFmpeg DLLs, mod.json saying geode 6.0.0-alpha.2 and gd `{win: 2.2091}`, no other platform's binary, and an about.md that says 2.2091 and not 2.2081.

## For the merge into master: pin the 2.2081 workflow's floating inputs too

The 2.2081 build still takes two inputs that move on their own:
- `geode-sdk/build-geode-mod@main` (twice in multi-platform.yml: the build and the combine step). Main was 61a56c697aea9655e3f31c6c1b83870431f30434 on 2026-11-16; its last change (2026-11-03) turned zstd on by default in the combine step.
- `gh:cursey/safetyhook#main` in CMakeLists.txt's Geode 5 branch. Main was f44cc070a8340f2f26649553c49533475417304d on 2026-11-16, the commit the local 2.2081 build has in build/_deps/safetyhook-src.

Pinning both to those commits should give the same 2.2081 file as today's CI (they are today's heads), but that's a change to the shipped 2.2081 build, so it needs Nigel's OK and one CI package compared against the last one before it lands (decision 12 in the parity plan). Do it in one commit: replace `@main` with `@61a56c697aea9655e3f31c6c1b83870431f30434` on both `uses:` lines, and in CMakeLists.txt fold the two SafetyHook branches into one pinned line.

Both actions still use `geode-sdk/cli/.github/actions/setup@main` inside themselves. That can't be pinned without a fork of the action.
