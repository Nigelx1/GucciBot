  - Fix: In GBR6Encoder::encode (gbr6_format.cpp:176-181), replace the single autoclick entry with chained entries of at most 65,535 cycles each. Leave prevFrame (line 183) and `i = sp.end` (185) as they are:
```
uint32_t left = cycles;
while (left > 0) {
    uint32_t const n = std::min(left, uint32_t(65535));
    out.push_back(0x00);
    out.push_back(pattern);
    out.push_back(static_cast<uint8_t>(n & 0xFF));
    out.push_back(static_cast<uint8_t>((n >> 8) & 0xFF));

}
```
The decoder needs no change. Each entry ends at start + n x (hold + release), which is where the next one starts, and there is no delta between them. That means older builds also read the new files correctly. The per-chunk acCycles value is harmless because nothing reads acCycles.
